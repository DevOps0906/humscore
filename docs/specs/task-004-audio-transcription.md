## 1. 목적·범위
악기 연주 음원 파일(MP3·WAV)을 지금보다 정확한 음표로 바꿀 수 있는지, 기기 안 실행으로 감당 가능한지를 스파이크로 판정한다. 오디오는 기기 밖으로 나가지 않는다.
- 근거: `01_PRD.md#3` P2 "음원 파일 업로드 → 음표 / 기기 안 변환(Basic Pitch)", `07_COMPETITORS.md#3` 입력 부족(음원 파일).
- 전략 제약: `07_COMPETITORS.md#4` 3항 "음원 전사 정면 승부는 피한다" → 목표는 **기존 '음원 등록'의 정확도 향상**이다(대표 기능·랜딩 CTA 아님).
- 현황 [확인]: task-014 '음원 등록'(`src/components/audio-import-dialog.tsx`) 파일 탭 = `framesFromAudioFile`(`src/lib/audio/offline-pitch.ts`, pitchy 단음, 50MB·10분 상한, 취소 가능) → `filterInstrumentFrames`(목소리 구간 제거) → `buildScoreFromFrames(range:"instrument")` → 바꾸기/뒤에 붙이기.

| 포함(스파이크) | 제외 |
|---|---|
| A(pitchy)와 B(Basic Pitch) 정확도·처리 시간·메모리 비교 | 제품 코드 병합, UI 변경 — 부록 A로 |

### 권고안 (스파이크 가설)
- B를 A 위에 얹는다(대체 아님). 파일 탭 기본 = B, 모델 로드 실패·추론 예외 시 A. 마이크 탭은 A 유지.
- 다성 결과는 멜로디 1성부(최고음)로 축약 → 기존 `buildScoreFromRawNotes` → `Score` 변경 없음.
- 스파이크(9장)에서 정확도·최고음 축약 품질 기준 미달이면 **중단(no-go)**, 의존성 문제만 걸리면 C 또는 A 유지로 재결정.
