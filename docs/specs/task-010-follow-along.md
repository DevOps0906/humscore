# task-010 따라 치기 연습 — 기능 명세

> 표기: **[확인]** = 코드·문서에서 직접 확인 / **[추정]** = 확인 전 추정 / **[미확인]** = 근거 필요. 수치는 초안이며 10장 결정 전 확정 아님.

## 1. 목적·범위
악보를 띄워 두고 실제 피아노를 치면, 들은 음이 "다음에 칠 음"과 맞는지 판정·표시하고 맞으면 진행한다.
- 근거: S3 피아노 독학자(`01_PRD.md#2`), 벤치마크의 "Wait 방식은 비용 대비 효과 클 수 있음(추정)"(`06_BENCHMARK.md` 시사점·후보 표).
- 우선순위: `01_PRD.md#3` 표에 이 기능 행이 **없음** → P1 후보로 제안(10장 #1).

| 포함 | 제외 (`01_PRD.md#6`) |
|---|---|
| 단음 멜로디(한 번에 한 음), 모드 "기다리기" | 화음·다성 판정, 점수·별점·랭킹, 커리큘럼·잠금 해제 |
| 마이크 / MIDI 건반 입력 | 박자(타이밍) 채점, 오디오 녹음·저장 |
| 쉼표 건너뛰기, 도돌이표 펼침 순서 | 음원 속 연주 채점, 틀린 음 보정 코칭 |

## 4. 판정 규칙 (순수 함수, `src/lib/music/` 신규)
| 항목 | 규칙(초안) | 상태 |
|---|---|---|
| 비교 단위 | 음이름 + 옥타브 = MIDI 번호 정수 일치. 목표는 `Score.notes[i].midi + transpose` | `Score`·`transpose` [확인](`types.ts`), 전조 적용 여부 10장 #4 |
| 마이크 주파수 → 음 | 주파수 → 가장 가까운 MIDI와 센트 오차 계산. 오차 **±50센트 이내**를 해당 음으로 본다 | 50센트는 반음 경계라 사실상 "가장 가까운 음". 더 좁힐지 10장 #5 |
| 안정 프레임 | 같은 음이 연속 **N프레임**(초안 N=3, 약 50ms @60fps) 유지돼야 확정 | N·프레임 간격 [추정]. 현재 tracker는 rAF마다 1프레임 [확인] |
| 신뢰도 | clarity 임계 사용. 악기 모드 기본 0.92 | `INSTRUMENT_MIN_CLARITY=0.92`, `range: "instrument"`(A0~C8) [확인] |
| 옥타브 오인식 | 피치 이름 일치 + 옥타브만 ±1 다름 → "옥타브 확인" 표시, 이동은 하지 않음(초안) | 배음 때문에 1옥타브 위·아래로 튈 수 있음 [추정]. 허용/불허 10장 #7 |
| 같은 음 연속 | 확정 후 입력이 **끊기거나(무음 프레임 M개) 레벨이 재상승**해야 다음 음 판정 시작 | M·재상승 비율 [추정], 실측 필요 |
| MIDI | `on` 이벤트의 `midi` 번호를 즉시 비교. 같은 음 연속도 `on`이 새로 오므로 자연히 구분 | `parseMidiMessage`·`MidiEvent` [확인](`midi-input.ts`) |
| 쉼표 | 목표 시퀀스에서 `midi === null` 제외 (대기하지 않음) | `NoteEvent.midi: null=쉼표` [확인] |
| 도돌이표 | 도돌이·D.C./D.S. 펼친 순서로 목표 시퀀스를 만든다 | `unrollScore`·`measureOrder`(`form.ts`) [확인] 존재. 입력·반환 형식은 구현 시 확인 |
| 틀린 음 | 목표와 다른 확정 음 → 틀림 표시. 연속 틀림은 같은 표시를 반복 갱신 | |
| 단음 가정 | 동시 타건(화음)·같은 박에 여러 `NoteEvent`는 이번 범위 밖 → 악보에 화음 있으면 안내(10장 #8) | 악보 모델이 화음 음표를 어떻게 담는지 [미확인] |

함수 시그니처(제안): `buildTargets(score) → number[]`, `judge(state, input) → {state, result}` — 상태는 불변 객체, 시간은 인자로 받는다(테스트 가능).

## 5. 입력
| 입력 | 현황 [확인] | 이번 작업의 필요 사항 |
|---|---|---|
| 마이크 | `startPitchTracking`이 에코제거·소음억제·AGC를 끈 채 요청(`pitch-tracker.ts`). 프레임은 `PitchFrame{time,freq,clarity}`. 결과는 프레임 배열 반환 + `onFrame` 콜백 | 연습은 `onFrame`으로 실시간 소비. 설정 끔 유지가 맞음(AGC가 켜지면 음량·배음 비율이 변해 오인식 증가 [추정]). 메트로놈 클릭은 끄기(`metronome:false`, `countInMeasures:0`) |
| 마이크 위험 | tracker `PitchDetector`(pitchy)는 단음용. 피아노 음은 배음이 강하고 감쇠하며, 화면 스피커 소리·잔향을 되먹임할 수 있음 | 옥타브 오인식·잔향 지속에 의한 다음 음 오인식 → 4장 규칙으로 완화, 실측 필요 [미확인] |
| MIDI | `connectMidi`(Web MIDI). iOS Safari 미지원 안내 문구 있음(`MIDI_UNSUPPORTED_MESSAGE`) | 정확도 높음. 소리 안 남(건반 자체 소리). iOS 앱 WebView 지원 여부 [미확인] |
| 화면 건반 | 88건반 화면 입력 있음(`06_BENCHMARK.md`) | 입력원으로 쓸지 10장 #9 |
- 사용자 안내: 마이크 모드는 "기기를 피아노 가까이, 주변 소음 줄이기"를 시작 전 1줄로 표시.
- 선율 재생 소리와 겹치면 안 되므로 연습 중 악보 자동 재생은 비활성(힌트 소리 기본 꺼짐).

## 7. 개인정보
- 마이크 오디오는 저장·전송하지 않는다. 피치 숫자(주파수·clarity)와 판정 결과만 메모리에서 쓰고 폐기(`01_PRD.md#6`, `#8` 민감 데이터).
- 연습 기록(횟수·틀린 음)을 저장할지는 10장 #6. 저장해도 음표 숫자 수준, 서버 전송은 새 결정 필요(보안 영향).
- 새 노출 면·키·의존성 없음 → 보안 레벨 변화 없음(`01_PRD.md#8` 기준). 새 의존성 추가 시 `secscan license`.
