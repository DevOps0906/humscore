# task-022 — 절별 가사·음표별 코드·작곡·리하모니제이션

## 범위와 데이터
- 가사 등록에서 `(1절)`~`(99절)`을 선택한다. 선택한 음표부터 해당 절만 적용하며, 삭제도 해당 절에만 적용한다.
- `NoteEvent.lyrics?: Record<string, string>`의 키는 `1`~`99`, 값은 최대 40자 음절이다. 기존 `lyric`은 1절로 읽고 새 1절 입력 시 함께 갱신한다.
- 절마다 음절 연결을 독립 계산하고, 악보·MusicXML에는 절 번호와 여러 가사 줄을 표시한다. 기존 단일 가사 악보는 그대로 읽는다.
- 코드 데이터는 기존 `ChordEvent.startBeat`를 사용한다. 선택한 음표 시작 박에 추가·수정·삭제하며 다른 위치의 코드는 보존한다.
- 화면은 전조한 코드·음높이를 보여 주고 원키로 저장한다. MusicXML·피아노 악보·반주에도 마디 안 코드 변경을 반영한다.

## 작곡
- 건반 화면과 저장된 악보에 `작곡` 버튼을 제공한다. 건반에서는 현재 입력을 저장한 뒤 작곡 도구를 연다.
- 선택: 1~32마디, 코드 진행 프리셋 또는 현재 진행, 균형·서정·리듬 선율, 마지막 마디 뒤 추가 또는 전체 교체.
- 코드 구성음·장/단음계·근접 진행·짧은 동기 변주·종지 패턴으로 새 후보를 생성한다. 특정 곡 데이터와 외부 AI·네트워크는 사용하지 않는다.
- 3/4·4/4·6/8을 지원하며, 후보는 선택 마디 길이를 정확히 채운다. 재생·음이름·악보로 확인한 뒤 적용한다.
- 후보 생성·취소는 원본을 바꾸지 않는다. 추가는 기존 음표·가사·기호를 유지하고, 교체는 기존 음표·가사·셈여림·진행 기호를 정리한다.
- 적용 후 한 단계 `작곡·리하모니 되돌리기`를 제공한다. 이후 다른 편집이나 외부 변경이 있으면 오래된 되돌리기를 사용하지 않는다.

## 고급 리하모니제이션
- 부드러운 대리 코드·재즈 화성·색채 화성 중 선택한다. 멜로디가 있어야 후보를 만들 수 있다.
- 멜로디와 코드 구성음의 적합도, 근음 이동, 기존 진행과의 차이를 평가해 마디별 코드를 제안한다.
- 기존/후보 진행·미리듣기·악보로 비교한 뒤 코드만 적용한다. 음표·절별 가사·셈여림·진행 기호는 보존한다.
- 후보는 음악 이론 기반의 제안이며 취향에 따라 직접 수정할 수 있다.

## 검증과 보안
- 단위: 절별 독립 적용·삭제·기존 호환·XML 표기·중간 코드·작곡 길이/음역/박자/변주·리하모 불변성·적용 위치·스키마 검증.
- 브라우저: 절 공존/새로고침, 선택 음표 코드 위치/전조, 후보 취소/추가/교체/되돌리기, 리하모 원본 보존, 3구간 배치.
- 서버 검증 스키마도 절별 가사를 보존한다. DB는 기존 `scores.data` JSONB를 사용하므로 테이블·RLS·마이그레이션 변경은 없다.
- 마이크 오디오 저장·전송은 추가하지 않는다. 음성 가사 입력은 기존 기기 내 인식과 사용자 적용 절차를 유지한다. 새 의존성 없음.
