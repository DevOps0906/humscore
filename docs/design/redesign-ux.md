# 랜딩·내 악보 재디자인 UX 초안

> 범위: L01 `/`, B01 `/library`. 구현 전 검토안이며 기존 개편 방향을 유지한다.
> 근거: [벤치마크 전체](../08_REDESIGN_BENCHMARK.md), [디자인 원칙](../../DESIGN.md), [L01·B01 화면·상태](../03_SCREENS_UX.md).
> 아래 ‘공통’, ‘차별’은 벤치마크의 공통 패턴·차별점 제안 번호다. 최근 작업·빈 상태 상세는 HumScore 자체 가설이다.

## 2. 랜딩 IA·섹션 와이어

목표는 ‘흥얼거리면 어떤 악보가 되는지 이해하고 가입 없이 시작’이다. 기존 개인정보 약속과 편집·내보내기 가치는 유지한다.

```text
[헤더: HumScore | 사용 방법·FAQ 앵커 | 내 악보(탐색 링크)]
[히어로: 흥얼거리면 악보가 됩니다]
[설명: 멜로디를 불러 음표와 코드가 붙은 악보로]
[주 CTA: 지금 흥얼거려 보기 → /record]
[보조: 가입 없이 · 마이크 소리는 기기 밖으로 나가지 않아요]
[결과 미리보기: 실제 출력 악보 캡처·제목·조·박자]
[사용 방법: 흥얼 → 악보 → 재생]
[비교 데모: 사용 허락된 샘플 허밍 재생 | 같은 멜로디의 실제 악보]
[활용: 편집·전조·연습·내보내기, 필요한 기능만 요약]
[개인정보·신뢰: 기기 안 처리와 음표 데이터 저장 범위]
[요금 요약: 무료 허밍 | 확정된 Pro 정보만 → /pricing]
[FAQ: 마이크 권한·인식 한계·저장·다른 기기에서 열기]
[하단: 지금 흥얼거려 보기 → /record | 푸터]
```

- 순서 보강: 결과를 기능보다 먼저, 3단계 바로 뒤 비교 데모 배치(공통 2, 차별 2, §1 Songscription 차용 1).
- 히어로는 결과 정지 화면, 비교 데모는 입력·출력을 함께 확인하는 영역으로 역할을 나눈다(자체 제안).
- 같은 CTA 문구·목적지를 반복한다. 건반 입력은 내 악보의 생성 진입 또는 마이크 오류 대안에 둔다(차별 1, §5 Soundtrap 차용 2).
- 후기·사용자 수는 검증된 자료 확보 전 숨긴다. 현행 통계 값의 진위는 이 초안에서 판단하지 않는다(차별 2).
- 요금 영역은 L01·DESIGN §4.4를 유지하되 미확정 금액·기능 약속은 게시하지 않는다. 상세 결정은 §7로 넘긴다.
- 데모 음성은 방문자의 녹음이 아닌 허락된 정적 샘플이다. 사용자 마이크 음성은 저장·전송하지 않는다.

## 3. 내 악보 IA·섹션 와이어

```text
[헤더: 내 악보 | 저장 범위 안내·계정 상태 | 악보 만들기]
[최근 작업: 최근 수정한 악보 최대 3개 | 제목·수정일·이어 작업]
[탐색: 전체 악보·1단계 폴더·최근 삭제 | 새 폴더]
[도구: 제목으로 검색·지우기 | 정렬 | 태그 필터·선택 해제]
[결과: 선택 범위·검색 결과 수 | 실제 악보 미리보기 카드]
[카드: 제목 → 조·템포·마디 → 수정일 | 더보기]
[목록 끝: 이전·다음 페이지 | 현재 페이지 안내]
[생성 진입: 허밍 시작(기본) | 건반으로 입력(보조)]
```

| 요소 | 동작·기준 | 근거 |
|---|---|---|
| 악보 만들기 | 헤더 우측 고정 위치. 열면 허밍을 기본 행동으로, 건반을 보조 행동으로 제시 | 차별 3, §2 Klangio 차용 3; 입력 방식은 기존 StartCard 유지 |
| 생성 진입 | 모바일 하단 마이크 ‘허밍 시작’은 `/record` 직행, 상단 생성 아이콘은 방식 선택. 중간 선택 화면은 새 경로 없이 시트·팝오버 | 차별 3 보강, §3 Flat 차용 3 |
| 최근 작업 | 수정일 내림차순, 전체 악보 범위에서만 노출. 검색·필터 적용 시 숨기고 결과에 집중 | 자체 제안; 경쟁사 최근 구분은 미확인 |
| 최근의 의미 | 우선 ‘최근 수정한 악보’로 명시. 단순 열람으로 수정일을 바꾸지 않으며 최근 열람 기록은 별도 결정 | B01 정렬 보강; Score 모델 변경 없음 |
| 검색 | 보이는 라벨 ‘제목으로 검색’, 공백 제거·대소문자 무시 부분 일치. 입력 시 목록 갱신·첫 페이지로 | §2 Klangio 검색 위치; 일치 방식은 자체 제안 |
| 정렬 | 기본 ‘최근 수정순’, 선택 ‘제목순’·‘최근 생성순’. 최근은 모호하게 중복 표기하지 않음 | B01 최근·제목·수정일을 구체화, §2 Klangio 이름·날짜순 |
| 적용 범위 | 검색·정렬은 선택 폴더와 태그로 좁힌 전체 결과에 적용하고 그 뒤 페이지를 나눈다. 조건은 상세 왕복 시 유지 | B01 pagination 보강; 자체 제안 |
| 폴더·태그 | 폴더는 중첩 없는 컬렉션, 넣어도 전체 악보에 남음. 태그는 보조 필터; 미구현 항목을 작동하는 것처럼 노출하지 않음 | 공통 4, §3 Flat 차용 1, §4 Noteflight 차용 2, B01 |
| 카드·메뉴 | 카드 본문은 `/scores/[id]`로, 더보기는 이름 변경·폴더 이동·삭제. 메뉴를 링크 안에 중첩하지 않음 | B01·DESIGN 결과 중심 원칙; 메뉴 상세는 자체 제안 |
| 최근 삭제 | 삭제 확인에 30일 복구 안내, 복구·영구 삭제를 구분하고 활성 목록·검색에서 제외 | 차별 3, §4 Noteflight 차용 1; 저장·복구 정책은 팀장 확정 |

최근 작업과 전체 목록의 중복은 ‘이어 작업’과 ‘찾기’ 목적 차이로 허용한다. 항목이 없으면 최근 영역을 숨긴다.

## 4. 상태별 행동·시작 흐름

| 화면·상태 | 표시·다음 행동 |
|---|---|
| 내 악보 최초 비어 있음 | ‘아직 악보가 없어요’ + ‘첫 멜로디를 흥얼거려 보세요’ + 허밍 시작·개인정보 문구. 검색·정렬·페이지는 숨김 |
| 폴더만 비어 있음 | ‘이 폴더에 악보가 없어요’ + 전체 악보 보기·악보 만들기. 다른 폴더의 악보가 없다고 오인시키지 않음 |
| 검색·필터 결과 없음 | 검색어·선택 범위 표시 + ‘조건에 맞는 악보가 없어요’ + 검색 지우기·필터 해제. 새로 만들기로 대체하지 않음 |
| 내 악보 로딩 | 헤더·생성 행동 유지, 목록 스켈레톤·‘악보 불러오는 중’. 초기 빈 상태를 먼저 보이지 않음 |
| 목록·검색 오류 | ‘악보를 불러오지 못했어요’ + 재시도, 조건 유지. 기존 결과는 남기고 오류를 결과 없음과 구분 |
| 랜딩 데모 실패 | 실제 악보 정지 이미지·설명 유지, 재생 실패 안내. 허밍 CTA는 계속 사용 가능 |
| 마이크 권한·지원 실패 | 시작 행동 뒤 권한 요청. 거부 시 설정 안내·재시도, 미지원이면 사유·건반 입력 대안 |
| 녹음 무음·결과 없음 | ‘인식한 음이 없어요’ + 다시 흥얼거리기. 빈 악보를 성공으로 표시하지 않음 |
| 악보 저장 실패 | 결과를 유지하고 재시도. 저장 완료 뒤에만 성공 안내·내 악보 이동 제공 |

흐름은 [Mermaid 원본](../diagrams/redesign-flow.mmd)을 따른다. 녹음·결과 화면은 연결 계약만 제시하며 이번 재디자인 범위에 포함하지 않는다.
비회원은 가입 없이 시작·기기 내 저장을 제안한다. 로그인은 계정 동기화의 선택 행동으로 두며 B01 로그인 명세와의 충돌은 §7에서 확정한다.

## 5. 반응형 3구간

| 화면·요소 | 모바일 ~767 | 태블릿 768~1199 | 데스크톱 1200~ |
|---|---|---|---|
| 랜딩 히어로 | 제목→CTA→정지 악보, 세로 | 세로 중앙, 설명 다음 결과 | 좌 설명·CTA / 우 결과 |
| 랜딩 본문 | 3단계 세로, 허밍 영상 위·악보 아래 | 단계 가로, 비교는 좌우 | 단계 가로, 비교 좌우·콘텐츠 폭 제한 |
| 랜딩 고정 CTA | 본문 CTA가 보이지 않을 때 하단 동일 행동 노출 | 본문·하단 CTA | 본문·하단 CTA |
| 내 악보 헤더·생성 | 상단 생성 아이콘 + 하단 큰 마이크 버튼 | 제목·우측 악보 만들기 | 제목·우측 악보 만들기 |
| 최근 작업·목록 | 카드 1열, 최근는 접기 가능 | 카드 2열 | 카드 3열 |
| 검색·정렬 | 검색 전폭, 다음 줄 정렬·필터 열기 | 검색·정렬 한 줄 | 검색·정렬 한 줄 |
| 폴더·태그 | 상단 폴더 칩 + 상세 필터 시트 | 상단 폴더 칩·태그 필터 | 좌 폴더·최근 삭제, 본문 태그 |
| 생성 방식 선택 | 하단 시트 | 버튼 옆 팝오버 | 버튼 옆 팝오버 |

- 태블릿 히어로는 DESIGN §4.1의 세로안을 우선한다. L01 표의 2열과 다른 점은 결과 가독성 확인 후 확정(공통 2·차별 2 보강).
- 모바일 필터 시트는 B01, 폴더 칩은 DESIGN §4.8을 함께 적용한다. 가로 스크롤은 칩 내부로 제한한다.
- 고정 CTA는 마지막 카드·페이지 이동·포커스를 가리지 않게 안전 영역을 확보하며 키보드·시트가 열리면 숨긴다.

## 6. 토큰·접근성 적용 계약

- 배경·면·본문·보조: `--color-paper`, `--color-surface`, `--color-ink`, `--color-ink-soft`; 악보 면: `--color-score-paper`.
- 주 행동: `--color-accent`, `--color-accent-ink`; 동일 화면에서 강조 면은 한 행동에만 부여한다. 반복 진입은 윤곽·텍스트로 표시한다.
- 제목·설명·본문·보조: `--text-5xl`, `--text-4xl`, `--text-xl`, `--text-base`, `--text-sm`; 글꼴: `--font-sans`, 수치: `--font-mono`.
- 경계·포커스·오류: `--color-line`, `--input`, `--color-ring`, `--destructive`; 카드·컨트롤: `--radius-2xl`, `--radius-lg`, `--shadow-sm`.
- 색·크기 값을 새로 정하지 않는다. 간격·터치 영역 등 필요한 미정 토큰은 DESIGN §5 검토 대상으로 연결한다.
- 검색 라벨·아이콘 이름·선택 텍스트·키보드 포커스를 제공한다. 결과 수는 상태 안내, 오류는 문구·아이콘으로 전달한다.
- 시트는 초점 진입·가두기·닫은 뒤 복귀를 제공한다. 데모는 자막·정지 대안, 동작 줄이기 설정을 지원한다.

## 7. 팀장 결정 필요·검증

- B01 로그인 필수와 가입 없는 체험·기기 내 저장의 연결, 계정 동기화 시점·문구 확정.
- ‘최근 수정’ 채택 또는 별도 최근 열람 기록 도입 여부, 폴더·태그·30일 복구 구현 순서와 데이터 정책 확정.
- 태블릿 히어로 세로안, 모바일 고정 생성 버튼의 기존 탐색 UI와의 겹침, 미정 간격·터치 토큰 확정.
- 실제 출력 캡처·허락된 샘플 확보, Pro 정보 공개 범위 확정. 후기·사용자 수는 자료 확보 후 재검토.
- 검증: 첫 방문의 허밍 시작, 재방문의 제목 검색·정렬·이어 작업, 빈 결과 해제·권한 거부 복구를 각 구간에서 확인한다.
- 사업 검증: 기존 무료 허밍·Pro 방향 유지; 가장 싼 검증은 이 와이어의 사용성 확인, 자동화는 상태·흐름 검사부터. 정부지원 연계는 별도 사업 판단이다.
